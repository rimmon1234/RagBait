## 3. Deep Architectural & Integration Verification

### 3.1 Authentication, Authorization & Isolation
- **Authoritative Identity**: Supabase GoTrue remains authoritative. All API endpoints use `get_current_user` and `require_approved_user`.
- **Role Isolation**: User (`user`), Administrator (`admin`), Super Admin (`super_admin`). Privileged endpoints enforce server-side role checks.
- **Credential Ownership & Sharing**:
  - `owner_only` credentials are inaccessible to other users or administrators via application APIs (`test_gateway_security.py` passes).
  - `community_shared` credentials require both `shared_consent = true` and `provider.allows_community_sharing = true`.
- **Node Agent Authentication**: Ed25519 signature verified on single-use 32-byte challenge nonces generated with 60-second TTL in dedicated Redis.
- **Session Fencing**: Authoritative in PostgreSQL (`active_session_id`, `session_epoch`). Reconnection increments the epoch monotonically; stale sessions are rejected.

### 3.2 Database & Migration Hygiene
- **Clean Reset Verification**: `npx supabase db reset` was executed on the local disposable database. All 11 migrations applied cleanly without errors:
  1. `20260101000000_ragbait_initial_schema.sql`
  2. `20260201000000_m2_provider_registry.sql`
  3. `20260202000000_m2_credential_vault.sql`
  4. `20260203000000_m2_credential_management.sql`
  5. `20260204000000_m2_admission_usage_ledger.sql`

  11. `20260209000001_m2_8_community_rls_hardening.sql`
- **pgTAP Test Suite**: All 142 pgTAP tests passed on the freshly reset database (`npx supabase test db`).
- **RLS Enforcement**: Authenticated users have restricted SELECT/INSERT/UPDATE permissions; sensitive columns (`status`, `validation_status`, `balance_microcents`) cannot be modified by user roles.

### 3.3 Credential Vault & KMS
- **Encryption**: AES-256-GCM authenticated encryption. Nonces, ciphertext, and tags stored in `public.api_key_vault`.
- **JIT Decryption**: Decryption occurs only at execution time in ephemeral memory; decrypted keys are never written to disk, PostgreSQL, or logs.
- **Production KMS**: `VAULT_MASTER_KEY` is documented for Google Cloud KMS or AWS KMS integration in production environments (`docs/VAULT_PROVISIONING.md`).

### 3.4 Admission Control & Usage Ledger
- **M2.4 Protections**: User RPM, Credential RPM, Provider/Model RPM/TPM, and daily/monthly spending caps enforced.
- **Single Source of Truth**: M2.9 routing reuses M2.4 `reserve_generation` and `settle_reservation`. It does **not** create a second rate limiter or ledger.
- **Distributed Concurrency Leases**: Leases managed via Redis sliding window counters and Sorted Sets with automatic TTL recovery.

### 3.5 M2.9 Intelligent Routing & Cost Calculation Audit
- **Pricing Formula Audit**:
  - The M2.4 convention defines `input_cost_per_million_cents` as cents per 1,000,000 tokens.
  - Since $1\text{ Cent} = 1,000,000\text{ Microcents}$, cost per token in microcents is directly `input_cost_per_million_cents`.
  - In `apps/api/app/modules/admission/ledger.py:compute_cost_microcents`:
    $$\text{cost\_microcents} = (\text{input\_tokens} \times \text{input\_cost\_per\_million\_cents}) + (\text{output\_tokens} \times \text{output\_cost\_per\_million\_cents})$$
  - In `apps/api/app/modules/routing/policy.py:scoring_key`:
    $$\text{microcents} = (\text{estimated\_input\_tokens} \times \text{c.pricing\_input\_cents\_per\_million}) + (\text{estimated\_output\_tokens} \times \text{c.pricing\_output\_cents\_per\_million})$$
  - **Verdict**: The routing policy formula matches the ledger formula **exactly**. Integer precision is maintained without truncation or float rounding.
  - Missing prices are represented as `None` and mapped to `999_999_999` (ranked last among metered models), never accidentally treated as free.
- **Server Default Models**:
  - `DEFAULT_CLOUD_MODEL = "gemini-3.8-flash"`: Validated present and active in `public.llm_models`.
  - `DEFAULT_COMMUNITY_MODEL = "llama3.2:3b"`: Standard model across community node fixtures and tests.
  - Model substitution is impossible when a client specifies a model; Filter 2 in `policy.py` rejects any candidate that does not match.
- **Privacy Boundaries**:
  - `cloud_only`: Never selects or falls back to community nodes.
  - `auto`: Requires explicit `community_opt_in: true` to evaluate community nodes; otherwise strictly cloud.
  - `community_only`: Requires explicit consent; fails closed with `409 Conflict` if no nodes are available; never falls back to cloud.
- **Idempotency**:
  - Request payload SHA-256 hash stored in `pricing_snapshot`.
  - Same key + different payload raises `409 Conflict`.
  - Cross-user key reuse is isolated by `user_id`.

### 3.6 Dedicated Community Redis Isolation
- **Separate Service**: `ragbait-community-redis` on port `6380`.
- **Volatile Configuration**: `--save ""` (RDB disabled), `--appendonly no` (AOF disabled), `--maxmemory-policy noeviction`.
- **Zero Prompt Disk Persistence**: No Docker volume mounted (`volumes` omitted for community Redis).
- **Environment Isolation**: `COMMUNITY_REDIS_URL` validated distinct from `REDIS_URL` at application startup.

### 3.7 Private Local Inference (M2.7 Regression)

- Zero backend proxying, zero database logging of private prompts/tokens.
- Unit and client mock tests pass (20 tests).

## 4. Confirmed Defects

### DEFECT-01 (Severity: Medium) — Community Dispatch Method Name Mismatch
- **Location**: `apps/api/app/modules/routing/executor.py:350`
- **Issue**: `auth_nonce = comm_crypto.generate_challenge_nonce()` calls a nonexistent function on `comm_crypto`.
- **Root Cause**: `apps/api/app/modules/community/crypto.py` does not define `generate_challenge_nonce()`. The community service (`apps/api/app/modules/community/service.py:380`) uses `secrets.token_hex(16)`.
- **Impact**: If the unified router dispatches a job to an eligible community node via `execute_community_candidate`, it will raise `AttributeError: module 'app.modules.community.crypto' has no attribute 'generate_challenge_nonce'`.
- **Remediation**:
  1. In `apps/api/app/modules/routing/executor.py`, import `secrets` and replace line 350 with:
     ```python
     auth_nonce = secrets.token_hex(16)
     ```
  2. Add an end-to-end integration test in `apps/api/tests/test_routing_execution.py` verifying that `route_and_dispatch` successfully signs and dispatches to a community node candidate.

### DEFECT-02 (Severity: Low) — Code Quality / Linter Warnings
- **Location**: `apps/api/app/modules/routing/executor.py`, `schemas.py`, `service.py`, `test_routing_policy.py`, `test_routing_security.py`.
- **Issue**: Unused imports (`json`, `AppError`, `typing.Any`, `AuthorizationError`, `pytest`, `httpx`) flagged by `ruff check`.
- **Remediation**: Remove unused imports and variables during the focused remediation turn.

## 5. External Deployment Requirements

The following requirements are external to the code repository and must be configured in production:

1. **Authentication (Supabase GoTrue)**:
   - Dedicated Supabase project with production JWT secret.
   - Configured SMTP credentials for student email verification.
   - Approved student email domain allowlist.
2. **PostgreSQL & Database Connection**:
   - Production PostgreSQL (15+) instance with `pg_crypto` and RLS enabled.
   - Separate connection pool limits for API and background workers.
3. **Dual Redis Infrastructure**:
   - **Persistent Redis (M2.4)**: High-availability instance with AOF persistence for rate limiting, quotas, and ledger concurrency leases.
   - **Dedicated Volatile Community Redis (M2.8)**: High-performance memory-only instance with `--save ""` and `--appendonly no`, zero persistent volumes.
4. **Cryptographic Key Management**:
   - `VAULT_MASTER_KEY`: 32-byte hex key backed by KMS (AWS KMS, Google Cloud KMS, or HashiCorp Vault).
   - `COMMUNITY_SERVER_SIGNING_KEY_HEX` / `COMMUNITY_SERVER_VERIFYING_KEY_HEX`: Production Ed25519 signing keypair for node authorizations.
5. **Network & Proxy Termination**:
   - HTTPS and WSS reverse proxy (e.g. Nginx, Cloudflare) with WebSocket upgrade support.
   - Accurate client IP forwarding (`FORWARDED_ALLOW_IPS`) for trustworthy rate limiting.
